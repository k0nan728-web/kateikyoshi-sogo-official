# 公式サイト お問い合わせ・お申し込みフォーム導入手順

ステータス: **公式フォームページと送信APIのコードは本番公開済み／メール配信・Turnstileの本番設定は未完了**。2026-10-12の本番API診断で `GET /api/intake` は HTTP 200 だが `available:false` と確認。独自フォーム内での送信は現在まだ動作しない。旧 Google フォームへの引き継ぎを維持し、送信設定と実受信テスト前に「直接送信できる」と案内しない。

## 構成

- `/contact/`：簡潔な無料相談・お問い合わせ（氏名、メール、相談種別・内容が必須）。既存 Google フォームの問合せ系6種類をカバーする。
- `/apply/`：体験授業・通常授業の申し込み希望（4ステップ）。**受講者のお名前・そのふりがな（ひらがな）・学年・お住まいの都道府県と市区町村は必須**。公立高校受験の都道府県別制度を踏まえ、オンライン指導でも地域を伺う。町名・番地は不要。旧フォームの講座、科目、時間、日時、希望曜日、オンラインツール、問い合わせ経路、学校名などを引き継ぐ。毎週の授業を開始できる曜日と開始時間帯は第1候補を必須、第2〜第4候補を任意とし、各候補について曜日・開始可能な最も早い時刻・最も遅い時刻を入力する。授業の終了時刻ではないことを明記し、候補が少ないと受け入れられない可能性が高まることを案内する。学校名・性別・診断名は必須ではない。性別・診断名は原則収集しない。
- `/intake/intake.js`, `/intake/intake.css`：共有 UI と挙動。?brand=eiken|gyakuten|bansou|retry で流入元判別とコース初期値。
- 旧Googleフォームの質問の内部 entry ID は公開フォームのHTMLから直接取得して照合したもの（2026-10-12時点）を使用する。既存Googleフォームの必須設問を変更した場合は再検証し、古い項目への事前入力を保証しない。
- `/functions/api/intake.js`：Cloudflare Pages Functions。サーバー側バリデーション、Cloudflare Turnstile、Resend 通知メール（宛先: info@kateikyoshi-sogo.com）、受付確認メール。
- ホームの問い合わせボタンは `/contact/` へ、専用申し込みリンクは `/apply/` へ（ブランチ内のみ）。
- **申し込みに関する同意**：正式な「利用規約」単独ページは現行公式サイトにないため、架空の規約に同意させない。公式トップの [授業料金・受講条件](https://kateikyoshi-sogo.com/#pricing)、[キャンセル規定](https://kateikyoshi-sogo.com/#cancel-policy)、[受講までの流れ](https://kateikyoshi-sogo.com/#process) を確認できるリンクと「公式サイト掲載の申し込み条件に同意する」未チェックの必須チェックボックスを設ける。既存の個人情報への同意も独立して必須にする。申し込み API は `siteTermsAccepted === true` と `privacyAccepted === true` を検証し、受付通知に含める。無料相談では正式受講条件の同意を必須にしない。
- **スマートフォンの見出し改行**：幅 600px 以下は主見出しを「体験授業・通常授業の」「お申し込み」の意味単位で2行表示し、申し込みフォーム見出しやナビゲーションも自然に改行する。中間端末は不要な強制改行を避け、320/390/768/1024/1366pxを確認する。全サイトの共通ルールは `SITE_READABILITY_STANDARDS.md` に反映する。

## 本番切替に必要な設定（Cloudflare Pages の対象プロジェクト）

Cloudflare Pages の Settings → Environment variables / Secrets 等、実際の公開設定画面で Production と Preview に次を登録する。**値そのものを GitHub に書き込まないこと。**

| 変数 | 必須 | 内容 |
| --- | --- | --- |
| `RESEND_API_KEY` | はい・Secret | Resend の送信用 API キー |
| `INTAKE_FROM_EMAIL` | はい | Resend で検証済みドメインの差出人。例: `鈴木雄太 <form@kateikyoshi-sogo.com>` |
| `TURNSTILE_SITE_KEY` | はい | Cloudflare Turnstile の公開サイトキー |
| `TURNSTILE_SECRET_KEY` | はい・Secret | Turnstile の秘密キー |

ドメイン `kateikyoshi-sogo.com` をメール配信サービスで検証し、指定した From からメールが送れることを先に確認する。DNS/メール設定で既存の受信設定を破壊しない。Turnstile で本番ドメインと実際のプレビュー用ホストを許可する。

`GET /api/intake` が `{"available":true,...}` を返した後にテストを始める。設定がそろわないプレビュー・本番では通常の独自送信は利用できない。その場合はボタンを無効化せず、入力内容を旧Googleフォームへ事前入力したページを開き、**Googleフォーム側の「送信」で最終受付する**。旧Googleフォームには現行の新フォームに存在しない必須設問（性別、学校名、希望科目、オンラインツール等）があるため、回答者はGoogleフォーム側で不足分を補う。勝手に性別等を補完したり、ページを開いただけで送信完了と判定したりしない。入力内容コピーと既存フォームへの直接リンクも用意する。専用フォームからの直接送信にはメール通知サービス設定と受信確認が必要。

## 実施必須の検証

1. **通知**：本人管理のテストメールアドレスから相談・体験申込・通常授業申込をそれぞれ送信して、宛先 `info@kateikyoshi-sogo.com` への到達と返信先メールアドレスを確認。Google フォームの既存の本物の記録は移行・削除しない。
2. **控えメール**：テスト利用者側へ受付確認メールが到達するか検証。迷惑メール箱も確認。
3. **未入力**：受講条件への明示的同意と個人情報の取り扱いへの同意が別々にチェックされていない申し込みは拒否する。お申し込み時の受講者名・ふりがな・学年・地域（都道府県・市区町村）のいずれかが未入力なら、画面とAPIの両方で受け付けないこと。毎週の開始時間帯は第1候補の曜日・開始時刻（早／遅）を必須とし、第2〜第4候補は完全に空欄でも可。ただし部分入力と時刻の逆転は拒否する。同じ開始時刻を「最早／最遅」に設定して指定することは許容する。お問い合わせはこれらを必須にしない。メール形式、希望講座未選択、同意チェック未選択も検証。
4. **送信失敗**：配信 API エラー、通信断、Turnstile エラーで「送信完了」と誤表示されず、旧フォームへの代替導線が残ること。
5. **セキュリティ**：TURNSTILE_SECRET_KEY と RESEND_API_KEY がHTMLやリポジトリに現れないこと。サーバーログに氏名・メール・相談内容を残さないこと。
6. **端末**：320 / 390 / 768 / 1024 / 1366 px、iPhone Safari、キーボード操作、200%ズーム。横スクロール・重なり・極小文字・タップしづらさがないこと。
7. **内容**：体験授業は「有料」、通常授業の契約は「送信しただけでは成立しない」を維持。英検等の受講コースと本人の指導可能範囲を確認。
8. **既存導線**：トップ、4ブランド、料金比較、メール、SNS、Googleフォーム、その他既存ページのリンクに後退がないこと。
9. **公開**：Cloudflare Pages の最新本番デプロイが成功し、公開 URL `/contact/` `/apply/` `/api/intake` を実表示確認すること。デプロイ失敗時は旧導線を保持・復旧すること。

## 完全独自送信を有効化するための残作業

2026-10-12時点の公開API診断の確認結果:

- `/apply/`: HTTP 200
- `/contact/`: HTTP 200
- `/api/intake`: HTTP 200（ただし `available:false`）
- Turnstile公開サイトキー: **なし**
- Googleフォームへの引き継ぎ: **あり**

### アカウントで必要な設定（秘密値はGitHubやチャットに貼り付けない）

1. Resendへログインして `kateikyoshi-sogo.com` の差出人ドメインを認証する。Resendで表示されるDNSレコードをCloudflare DNSに設定する際、**既存のメール受信設定（MXなど）は壊さない**。認証済みの `From` を用意する。
2. Resend APIキーを生成し、Cloudflare Pagesの**本番（Production）**にSecret `RESEND_API_KEY` を登録する。通常の環境変数 `INTAKE_FROM_EMAIL` にResendで確認済みの送信元を設定する。
3. CloudflareのTurnstileで本番サイト `kateikyoshi-sogo.com` と `www.kateikyoshi-sogo.com` を許可したウィジェットを作成し、サイトキー `TURNSTILE_SITE_KEY` とSecret `TURNSTILE_SECRET_KEY` をCloudflare Pagesの**本番（Production）**に設定する。プレビューテストも実施する場合はPreview環境用も設定する。
4. Pagesの本番デプロイを再実行。 `GET https://kateikyoshi-sogo.com/api/intake` が `available:true` を返すことを確認。
5. 申し込みフォームからユーザー本人管理のメールで体験授業／通常授業を試験送信し、`info@kateikyoshi-sogo.com` への通知と返信先、希望候補、第1〜第4候補、規約同意、お客様への自動返信を確認する。実受信の確認まではGoogleフォームの代替導線を残す。

### 自動検証

- `node intake/validate.test.mjs` — 必須項目、受講条件・個人情報同意、第1〜第4候補の検証。
- `node intake/native-delivery.test.mjs` — **実送信はしない**。Turnstileを模擬し、講師通知・控え・エラー時の返答を仮想的に検証。
- GitHub Actions `Check native form delivery readiness` — 個人情報を送らず、本番のGETと設定有無を確認。
- 本番 `available:true` になってから、実機Safari・スマホの入力→送信→実メール到達テストを行う。

**Go / No-go:** 本番APIが `available:true`、ドメイン認証と実メール到達が確認できるまでは、直接送信機能が有効になったとみなさない。個人情報の安全のため、秘密鍵のGitHubコミット・チャット送信は禁止。
